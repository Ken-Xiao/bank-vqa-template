# 入口信息架构重构设计说明

## 目标

把 Launch 页从“先填口径”的表单入口，调整为“先选择工作方式”的工作台入口。用户进入产品后的第一层决策应是：从数据开始，还是从报告开始；第二层决策才是按角色进入最合适的分析深度。

## 当前上下文

当前应用已经具备以下基础：

- `js/42-portal-router.js` 负责一等页面路由。
- `js/43-page-rail.js` 负责左侧 Page Rail 导航。
- `js/55-benchmark-page.js` 已经提供独立的数据对标页。
- Launch 页仍以目标银行、对标组和背景说明为主，用户需要先理解配置表单，才能知道后续能进入哪些分析路径。

因此，本次重构不重写分析引擎，也不改变深层页面结构，只调整首屏入口顺序和路由语言。

## 入口模型

Launch 页新增 `entry-decision-panel`，放在现有 setup workbench 之前。

### 主工作流入口

- `数据入口`：路由到 `benchmark`。用于选择目标银行、设置对标组、查看 9 个数据域、阅读指标卡和因果链分解。
- `报告入口`：路由到 `report`。用于审阅正式报告、收集数据对标附录、调整报告结构并导出交付件。

### 角色入口

- `董事会 / 行长室`：路由到 `answer`。默认关注 30 秒总判断、董事会议题和行动优先级。
- `CFO / 财务`：路由到 `benchmark`。默认关注指标矩阵、公式口径、趋势分位、分解和可入报告的附录证据。
- `CRO / 风控`：路由到 `topics`。默认关注资产质量、对公与零售风险、IFRS9、拨备和风险机制链。
- `研究 / 专家`：路由到 `data`。默认关注字段覆盖、三源对照、血缘关系和口径复核。

## 交互规则

所有入口卡片都使用现有 `data-page-link` 属性触发路由，不新增第二套路由状态。入口卡片只负责跳转，不修改目标银行、对标组、年份或报告状态。现有 setup 控件仍保留在入口面板下方，供需要先配置样本边界的用户使用。

角色入口额外携带 `data-entry-audience`。点击角色入口时，router 会把角色写入 `benchmarkiq.entryRole`；如果目标页或后续模块需要按角色切换默认视图，可从该值读取。进入 benchmark 的角色入口同时写入 `benchmarkiq.audience`，让数据对标页直接进入对应受众视图，避免用户再次选择 CFO / CRO / Board。

## 视觉方向

入口面板应像一个安静、专业、可扫描的银行经营工作台，而不是营销首页：

- 主工作流卡片比角色卡片更醒目。
- 卡片使用清晰边框、克制背景和 6px 圆角。
- 不使用装饰性渐变球、嵌套卡片或大面积宣传文案。
- 按钮有明确 hover 和 active 反馈，但动画保持短促。
- 移动端下，主入口和角色入口都退化为单列。

## 成功标准

- Launch 页首屏包含两个主工作流入口和四个角色入口。
- 每个入口卡片都通过 `data-page-link` 指向现有页面。
- 角色入口通过 `data-entry-audience` 持久化角色意图。
- Page Rail 的页面名称和摘要体现“数据入口 / 报告入口 / 角色入口”的心智模型。
- 原有 setup 控件仍可在入口面板下方使用。
- 契约测试覆盖入口卡片、路由标签和 CSS hooks。
