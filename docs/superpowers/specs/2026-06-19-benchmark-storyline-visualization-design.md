# 数据对标页故事线图谱展示设计

日期：2026-06-19  
范围：`outputs/vqa_template` 数据对标页  
状态：待实施计划

## 1. 背景与问题

当前数据对标页已经具备 9 个对标域、34 条故事线、148 个指标的数据基础，但页面默认露出的指标偏少，用户进入后看到的图表密度不足，难以体现“目标银行 vs 对标银行”的完整诊断价值。

同时，当前页面存在“相关性举证 / 相关性矩阵”类入口。这类入口更像研究工具，不适合作为管理层数据对标的默认展示。它会让用户先看到统计关系，而不是先看到目标行与对标组之间的经营差距。

本次设计的目标是：保留首页简洁性，同时让数据对标页真正使用指标库中的核心指标，自动生成更多可解释图表。

补充要求：图表不能只表现单项指标的数值差异，还要呈现有故事性关联的指标之间的传导关系。视觉上可以更多使用图库中的咨询风格图片、报告式信息图和业务场景图，让页面从“指标看板”升级为“可进入报告的证据图谱”。

## 2. 设计原则

1. **先故事线，后指标墙**  
   默认不展示 148 个指标的平铺表，而是按故事线组织指标。用户先看到“问题链”，再展开查看该问题链下的指标。

2. **先对标差距，后相关关系**  
   本轮移除相关性举证作为默认展示，不再展示“相关性矩阵”。每张图都围绕目标银行、对标银行、同类型均值或区域均值之间的差距来组织。

3. **图表由指标库驱动**  
   图表不是手写固定几项 KPI，而是从 `benchmark_metrics_catalog.md` 和 `data_benchmark.js` 对应的 domain/story/item 结构中读取指标。

4. **首屏只给关键问题，展开才给全量指标**  
   首屏展示 3 条最值得看的故事线；域内展开后展示该域下全部故事线；每条故事线可展开到全量指标。

5. **管理层视角优先**  
   默认展示“这家行与对标组差在哪里、差距说明什么、下一步该看什么”，而不是先展示统计口径或算法细节。

6. **图像服务于证据叙事**  
   图片不是装饰背景，而是辅助说明经营逻辑。每张图片或信息图都需要绑定一个故事线，例如“负债成本抬升压缩息差”“高风险行业集中推高资产质量压力”“资本占用上升压低 ROE”。

## 3. 推荐方案：故事线图谱

采用“故事线图谱”作为数据对标页主展示方式。

页面结构分为四层：

1. **顶部样本条**  
   显示目标银行、对标银行/对标组、分析年份、身份视角，并保留“重新选择”入口。

2. **重点故事线推荐区**  
   系统从 9 个域中自动推荐 3 条最值得优先看的故事线。推荐逻辑基于：
   - 目标行与对标组的差距绝对值；
   - 指标方向，判断差距是优势还是压力；
   - 指标覆盖率，覆盖不足的指标不进入强推荐；
   - 近 6 年趋势是否恶化或改善；
   - 是否属于精选指标（`★`）或核心故事线。

3. **域切换与故事线列表**  
   保留 9 个域：盈利能力、息差与定价、资产质量、对公贷款结构、零售贷款结构、存贷结构、流动性与监管、IFRS9 三阶段、资本与规模。  
   每个域下展示故事线卡片，而不是只展示少数单指标图。

4. **故事线详情图表组**  
   用户点击故事线后，右侧生成 2-3 张图：
   - 横向对比图：目标行 vs 对标银行 / 同类型均值 / 区域均值；
   - 六年趋势图：目标行与对标组均值的 2020-2025 趋势；
   - 结构拆解图：适用于收入结构、存款结构、贷款行业结构、IFRS9 阶段分布等；
   - 风险矩阵图：适用于对公行业占比 × 不良率、零售产品占比 × 不良率等。
   同时增加“关系图 / 传导图”作为故事线图谱的核心图形，用来表现多个指标之间的逻辑链条。

## 4. 首屏信息架构

数据对标页进入后默认显示：

1. **当前对标样本**
   - 目标银行；
   - 对标银行数量；
   - 分析年份；
   - 选定身份视角；
   - “重新选择”按钮。

2. **本轮优先看的 3 条问题链**
   每条卡片包含：
   - 故事线名称；
   - 所属域；
   - 差距方向：优势 / 压力 / 中性结构差异；
   - 主要支撑指标 2-4 个；
   - 一句话结论；
   - 按钮：查看图表。

3. **全部域入口**
   域标签不再只是切换少数图表，而是切换该域的故事线组。

## 5. 图表组件设计

### 5.1 横向对比图

用于多数指标。

展示对象：
- 目标银行；
- 自选对标银行；
- 全国同类型均值；
- 本地同类型均值；
- 全行业均值（如用户启用）。

图表规则：
- 目标银行使用高亮色；
- 对标银行使用中性色；
- 均值使用虚线或浅色柱；
- 根据指标方向自动标记“高于同业 / 低于同业 / 中性差异”。

### 5.2 六年趋势图

用于 ROA、ROE、NIM、不良率、拨备覆盖率、存贷比、资本充足率等有连续数据的指标。

图表规则：
- 目标银行为主线；
- 对标组均值为辅线；
- 可标注 2020、2025 两端差距；
- 如果趋势方向与 2025 横截面结论冲突，显示“需复核”提示。

### 5.3 结构拆解图

用于结构类故事线：
- 收入结构；
- 利润传导；
- 存款期限结构；
- 贷款产品结构；
- IFRS9 三阶段分布；
- 资本效率分解。

图表规则：
- 使用 100% 堆叠条、瀑布图或小多图；
- 不把结构类指标硬判好坏，重点解释结构差异。

### 5.4 风险暴露矩阵

用于对公贷款结构、零售贷款结构、风险行业等故事线。

图表规则：
- X 轴为占比；
- Y 轴为不良率或风险强度；
- 气泡大小为加权风险暴露；
- 右上区域定义为核心风险区；
- 目标行高亮，对标银行低饱和显示。

### 5.5 故事性关联图

用于表现指标之间的传导关系，而不是单纯比较某个指标高低。

典型关系：
- ROE 低 → ROA 低 → 净息差低 → 存款定期化率高 / 负债成本高；
- 不良率高 → 拨备计提压力高 → 净利润承压 → ROE 承压；
- 对公行业集中度高 → 风险行业暴露高 → 不良生成压力高；
- 低收益资产占比高 → 生息资产收益率低 → NIM 承压；
- 核心一级资本充足率压力 → 风险加权资产扩张受限 → 贷款增长受限。

图表规则：
- 使用从左到右的因果链、桑基式流向、树状归因或分层卡片；
- 每个节点必须绑定一个指标值、对标均值和差距；
- 连线不表达统计相关性，只表达业务逻辑和指标传导关系；
- 节点按“结果指标 → 一级原因 → 二级原因 → 证据指标”展开；
- 用户点击任一节点，可以展开该节点对应的横向对比图或趋势图。

### 5.6 咨询风格图片与信息图

用于增强页面的报告感和故事感，但必须与数据证据绑定。

可用类型：
- **业务场景图**：银行网点、柜台、信贷走访、企业客户、制造业园区、县域经营场景，用于贷款结构、存款结构和客户经营类故事线；
- **报告式信息图**：流程图、价值链图、经营飞轮、风险漏斗、资产负债传导图，用于展示多个指标之间的关系；
- **专题页配图**：盈利能力、息差、资产质量、资本约束等专题可以使用低饱和、留白充足的咨询风格图片作为局部视觉锚点；
- **图表组合背景**：浅色底纹、分区面板和小型插画可以承载指标组，但不喧宾夺主。

使用规则：
- 图片必须来自项目图库、既有咨询风格素材或明确授权素材；
- 不使用纯装饰性大图，不使用与银行经营无关的抽象背景；
- 图片面积不超过故事线详情区的三分之一，核心仍然是图表和证据；
- 每张图片旁必须有对应的指标结论或传导关系说明；
- 默认优先使用图表化信息图；真实场景图只用于增强行业语境。

## 6. 移除与降级内容

以下内容不再作为默认展示：

1. **相关性矩阵**
   - 从数据对标页主视图移除；
   - 不再作为默认举证方式；
   - 如保留，可放入专家模式或后续研究工具，不进入首屏。

2. **固定 5-8 个 KPI 的卡片式展示**
   - 保留为故事线摘要中的“核心指标条”；
   - 不作为主要内容。

3. **泛化结论**
   - 页面文案必须绑定指标名、差距、对标对象；
   - 不使用“值得关注、持续跟踪、结构承压”等无证据表达。

## 7. 数据流

1. 用户选择目标银行、对标银行、年份和身份。
2. `js/55-benchmark-page.js` 从 `_bm.data.domains` 读取所有域、故事线、指标。
3. 新增故事线评分函数，对每条故事线计算：
   - 可用指标数；
   - 精选指标数；
   - 目标行 vs 对标组差距；
   - 趋势变化；
   - 覆盖率质量；
   - 是否可生成图表。
4. 页面默认展示排名最高的 3 条故事线。
5. 用户切换域后，展示该域下的全部故事线。
6. 用户点击故事线后，按故事线的 `chart_type / item list / domain` 自动渲染对应图表组。
7. 对于有因果链配置的故事线，系统额外生成“故事性关联图”，把结果指标、原因指标和证据指标组织成传导链。
8. 页面按故事线域匹配咨询风格图库或信息图模板；如没有匹配素材，则使用纯图表布局，不强行显示图片。
9. 用户确认数据包时，选中的故事线、指标、差距、关系链和图表说明进入证据包，后续报告页读取证据包。

## 8. 交互行为

1. **默认推荐**
   页面进入后，如果已有目标行，则自动生成推荐故事线；如果没有目标行，则显示选择提示。

2. **域切换**
   点击域标签后，左侧或顶部显示该域下故事线，右侧显示选中故事线图表组。

3. **展开指标**
   每张故事线卡片提供“展开全部指标”，显示该故事线包含的指标、值、对标均值、差距和覆盖率。

4. **加入证据包**
   用户可以把故事线加入报告证据包；证据包不再只接收单个指标，而是接收“故事线 + 指标 + 关系链 + 图表说明”。

5. **空数据处理**
   如果某个指标目标行或对标组缺数据：
   - 不展示空图；
   - 在指标行显示“该指标公开披露不足”；
   - 推荐评分中降低该故事线优先级。

## 9. 验收标准

1. 数据对标页不再显示相关性矩阵作为默认模块。
2. 数据对标页首屏至少展示 3 条由指标库自动生成的故事线推荐。
3. 每条推荐故事线至少引用 2 个真实指标。
4. 每个域能看到该域下的故事线列表，而不是只看到少数 KPI。
5. 点击故事线后能生成至少 2 类图表：横向对比和趋势图；结构/风险类故事线生成对应拆解图或矩阵图。
6. 对存在指标传导关系的故事线，详情页必须生成一张故事性关联图，节点至少包含 3 个指标。
7. 咨询风格图片或信息图只在能绑定故事线证据时展示，不能作为纯装饰背景。
8. 图表根据目标银行和对标银行的选择实时变化。
9. 证据包能记录故事线、指标、差距、关系链和图表类型。
10. 页面冷启动仍然进入数据对标，不被旧 hash 或 localStorage 带到结论摘要。

## 10. 不在本轮范围

1. 不新增外部数据源。
2. 不重做报告工作室。
3. 不做相关性矩阵或统计显著性展示。
4. 不重构全部 benchmark 数据构建脚本。
5. 不将 148 个指标全部同时平铺到首屏。
6. 不引入未经授权的外部图片素材；如图库没有合适图片，本轮使用信息图模板替代。
