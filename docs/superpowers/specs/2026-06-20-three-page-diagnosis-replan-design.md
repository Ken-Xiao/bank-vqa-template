# 结论摘要、证据地图、专题归因三页重规划设计

## 1. 背景与问题

当前 `answer / evidence / topics` 三个页面共用 `step2Content`，页面内同时挂载 30 秒诊断、同业位置、异动偏离、估值答案、专题入口、行动路径和多个高级深钻模块。结果是：

- 结论摘要页不够像“摘要”，用户进入后仍看到证据、专题、行动等多类内容。
- 证据地图页既有证明逻辑，又混入解释性文字和专题深钻，页面重心不稳定。
- 专题归因页默认暴露过多交叉信号、衍生分析和深钻 mount，像内容仓库，而不是管理层可读的问题链。
- 三页虽然共享证据包，但缺少明确分工，导致内容重复、语言泛化、用户不知道下一步该看什么。

本次重规划采用“结论 → 证据 → 归因”的单任务链条：每个页面只回答一个问题，其他内容收进可展开区或移到报告编排。

## 2. 设计目标

1. **结论摘要页只回答：本轮最重要的经营判断是什么。**  
   不再承载证据地图、专题深钻和大量行动项，只给董事会/行长能快速读完的一页判断。

2. **证据地图页只回答：这个判断为什么可信。**  
   用同业位置、异动偏离、估值/质量锚三类证据证明主判断，不再展开专题机制。

3. **专题归因页只回答：关键问题链如何传导。**  
   每次聚焦 1 个主问题链，展示“结果指标 → 直接原因 → 结构原因 → 管理动作”，高级分析默认折叠。

4. **三页全部由已确认的数据对标证据包驱动。**  
   页面不得脱离目标银行、对标银行、年份和已确认 issue 生成泛化表述。

5. **为后续报告页库留接口。**  
   三页中的主判断、证据块和归因链都应能转成“可加入最终报告”的 PPT 页面。

## 3. 推荐方案

采用 **A：三页单任务重构，并吸收 C 的折叠减载**。

不采用 B 的原因：把三页都改成 PPT 页面库入口会让“分析页面”和“报告编排页面”边界再次混合。报告页库应在分析链条之后承接，而不是替代分析链条。

不采用纯 C 的原因：只隐藏内容、改文案，无法解决根因。当前根因是页面职责没有分开，而不是内容数量本身。

## 4. 页面职责

### 4.1 结论摘要页：一句话总答案

页面定位：管理层进入报告分析后的第一屏。

核心问题：  
**“这家银行当前最需要管理层关注的经营质量约束是什么？”**

页面结构：

1. **一句话总答案**
   - 来自已确认 evidence pack 的 top issue。
   - 格式：`目标银行 + 年份 + 判断 + 主要约束 + 对标参照`。
   - 示例：`农业银行 2025 年经营质量主线不是规模扩张，而是盈利转化与息差防守能否继续支撑 ROE。`

2. **三张主判断卡**
   - 卡 1：主约束是什么。
   - 卡 2：最强证据是什么。
   - 卡 3：下一页应验证什么。
   - 每张卡最多 1 个核心指标 + 1 句解释。

   生成规则：

   - **排序来源**：优先使用已确认 evidence pack 的 `selectedIssues`；若为空，使用 `recommendedIssues` 前 3 个；若两者都为空，页面进入“证据不足”状态，不生成占位卡。
   - **卡 1 必显**：取 top issue，显示主约束和最核心指标。
   - **卡 2 优先取直接相关证据**：从 top issue 的 `evidence` 或 `causalChain` 中选择与卡 1 不重复的指标；如果 evidence pack 中没有下一层证据，则从第 2 个 issue 选取。
   - **卡 3 优先取下一步验证点**：从 top issue 的 `structureDriver / action / causalChain[2]` 生成；如果没有可追溯字段，则从第 3 个 issue 选取。
   - **不足 3 张时隐藏卡片**：不得为了凑满 3 张写泛化文案。1 个 issue 只显示 1-2 张；2 个 issue 最多显示 2-3 张；无可追溯证据时整张卡隐藏。
   - **去重规则**：同一 `metric / primaryMetric / evidenceId` 不应出现在两张主判断卡中；若重复，保留优先级更高的一张。

3. **最小 KPI 条**
   - 只保留 4-5 个核心数字。
   - 数字来源必须来自证据包或当前对标状态。
   - 不展示全量指标矩阵。

4. **进入下一步**
   - 主按钮：`查看证据地图`。
   - 次按钮：`重新选择数据对标`。
   - 不直接展示专题深钻。

不应出现：

- 多个专题卡片。
- 高级模型解释。
- 复杂图表矩阵。
- 行动路线全展开。

### 4.2 证据地图页：三类证据证明主判断

页面定位：把结论摘要中的判断变成可复核证据。

核心问题：  
**“这个主判断是否有足够证据支撑，可以进入正式报告？”**

页面结构：

1. **证据判断头**
   - 显示当前证据包状态：已确认 / 过期 / 需重新生成。
   - 显示证据强度：强 / 中 / 弱。
   - 显示数据边界：目标行、对标组、年份。

   证据强度规则：

   - 证据地图分为三类证据：`同业位置`、`异动偏离`、`估值/质量锚`。
   - 每类证据形成一个 `signalDirection`：支持主判断 / 反向 / 不足。
   - **强证据**：至少两类证据支持主判断，且没有强反证；或三类证据中有两类为强、中强度且方向一致。
   - **中证据**：仅一类证据支持主判断，另一类证据不足，且无明确反证；或两类证据方向一致但数据覆盖不足。
   - **弱证据**：只有一类弱证据、存在明显反证、证据包字段缺失、对标组不足 3 家，或证据包不是 confirmed 状态。
   - 第一版算法可以采用规则引擎：`supportCount >= 2 && counterCount === 0` 为强，`supportCount >= 1 && counterCount === 0` 为中，其余为弱；后续再叠加数据覆盖率和时间跨度。

2. **三栏证据地图**
   - 左栏：同业位置  
     说明目标行相对同类型/同区域对标组的位置。
   - 中栏：异动偏离  
     说明本期变化、偏离方向和是否与同业差距扩大。
   - 右栏：估值/质量锚  
     说明 PB、ROE、资产质量或资本效率是否支撑主判断。

3. **证据链摘要**
   - 将三栏证据压缩成一条逻辑链。
   - 格式：`位置证据 → 变化证据 → 估值/质量含义`。

4. **证据冲突与风险边界**
   - 只列最多 2 条反证或口径风险。
   - 如果证据不足，必须降低结论语气。

5. **进入下一步**
   - 主按钮：`进入专题归因`。
   - 次按钮：`回到结论摘要`。

不应出现：

- 详细专题机制。
- 多个高级 mount 同时展开。
- 大量解释系统方法论的文字。

### 4.3 专题归因页：一个主问题链

页面定位：解释“为什么会这样”，并形成报告页候选。

核心问题：  
**“主问题沿着哪条因果链传导，管理层应先看哪一环？”**

页面结构：

1. **专题选择器**
   - 默认选中证据包 top issue 对应专题。
   - 其他专题以小型列表显示，不默认展开。
   - 专题数量建议控制在 3 个以内：主专题 + 2 个备选专题。

   专题数量规则：

   - 若 evidence pack 识别出 1-3 个专题，全部显示。
   - 若识别出 4 个及以上专题，只显示 `主专题 + 2 个备选专题`；其余进入“更多专题”折叠列表。
   - 排序优先级：证据强度 > 与 top issue 的因果距离 > 是否有 reportCandidates > issue priority。
   - 折叠列表必须显示数量提示，例如：`另有 4 个专题已折叠`。
   - 不得丢弃专题数据；折叠只是 UI 减载，模型仍保留完整 `allTopics`。

2. **一条主因果链**
   - 结构固定为四段：
     - 结果指标：如 ROE / NIM / PB / 不良率。
     - 直接原因：如息差、成本收入比、资产质量。
     - 结构原因：如定期化率、贷款结构、拨备策略、资本消耗。
     - 管理动作：如负债结构复盘、贷款定价、风险确认、资本约束。

3. **专题证据卡**
   - 每条链最多展示 3 个证据点。
   - 证据点必须可回跳到证据地图或数据对标。

4. **报告页候选**
   - 展示“可加入最终报告”的 1-2 个页面候选。
   - 候选页只显示标题、核心图、证据句和使用场景。
   - 不在本页变成完整报告编排器。

   `reportCandidates` 数据契约：

   ```js
   {
     id: "report_<issueId>_<layout>",
     sourceIssueId: "profitability_pressure",
     title: "盈利能力承压专题页",
     chartType: "bridge" | "comparison" | "chain" | "matrix" | "visual",
     visualAsset: { src, label, caption } | null,
     evidenceSentence: "ROE 低于对标组，主要由 NIM 与成本收入比拖累。",
     useScenario: "董事会汇报" | "管理层行动" | "资本市场沟通",
     recommendedSlideLayout: "headline-evidence-chart" | "causal-chain" | "risk-map",
     context: { targetBank, peerGroup, year, issueId },
     trace: [{ field, source, value }]
   }
   ```

   字段来源：

   - `sourceIssueId / evidenceSentence / context / trace` 来自 evidence pack。
   - `chartType / recommendedSlideLayout` 由前端根据专题链类型生成。
   - `visualAsset` 优先使用 storyCards 或 evidence pack 中已有图片；没有图片时为 `null`，渲染层显示“暂无证据图”，不得使用无关装饰图。

5. **高级深钻折叠区**
   - 交叉信号引擎、利润质量、估值模型、现金流深度等保留，但默认折叠。
   - 展开按钮文案统一为：`展开更多机制证据`。

不应出现：

- 所有专题同时铺开。
- 全部深钻模块默认显示。
- 和结论摘要重复的总判断。

## 5. 数据模型与页面输入

三页共同读取 `benchmarkiq.evidencePack` 或 `readEvidencePack()`。

统一页面模型建议：

```js
{
  context: {
    targetBank,
    peerGroup,
    year,
    status
  },
  conclusion: {
    headline,
    topIssues,
    kpis,
    nextQuestion
  },
  evidenceMap: {
    strength,
    peerPosition,
    anomalies,
    valuationAnchor,
    counterEvidence
  },
  attribution: {
    activeIssueId,
    chain,
    evidence,
    reportCandidates,
    allTopics,
    foldedTopics
  }
}
```

页面不能直接从散落 DOM 或旧 `topicDefinitions()` 拼泛化结论；旧函数可以作为 fallback，但默认入口应是证据包模型。

### 5.1 可追溯文案规则

所有结论文案必须能回溯到 evidence pack 的具体字段。页面模型中每条判断应携带 `trace`：

```js
{
  text: "农业银行本轮主判断...",
  trace: [
    { field: "recommendedIssues[0].primaryMetric", value: "ROE" },
    { field: "recommendedIssues[0].evidence[0].gap", value: "-1.2pct" }
  ]
}
```

如果某句话没有 trace，渲染层不得显示为强判断，只能进入“待验证说明”或隐藏。

## 6. 导航与交互

三页路径：

`数据对标 → 确认证据包 → 结论摘要 → 证据地图 → 专题归因 → 报告页面库`

左侧任务栏顺序建议：

1. 数据对标
2. 结论摘要
3. 证据地图
4. 专题归因
5. 报告编排
6. 数据复核

页面内交互：

- 结论摘要：只提供下一步和重新对标。
- 证据地图：每个证据块可跳回数据对标对应指标/故事线。
- 专题归因：专题选择器控制主链；高级深钻默认折叠。

## 7. 空状态与过期状态

0. **加载中**
   - 读取 evidence pack 或等待 benchmark 同步时显示 skeleton。
   - 文案：`正在读取本轮证据包...`。
   - 不显示旧页面残留内容。

1. **没有证据包**
   - 三页显示同一类空状态：`请先完成数据对标并生成证据包`。
   - 主按钮跳回数据对标页。

2. **证据包过期**
   - 页面顶部显示黄色提示：`目标行、对标组或年份已变化，请重新生成证据包`。
   - 不继续生成新结论，避免错用旧数据。

3. **证据不足**
   - 结论摘要使用审慎语气。
   - 证据地图显示弱证据状态。
   - 专题归因只展示“待验证链条”，不生成强判断。

4. **字段缺失或部分失效**
   - 如果 evidence pack 存在但缺少 `recommendedIssues / selectedIssues / targetBank / peerGroup / year` 中的关键字段，页面进入 `partial-pack` 状态。
   - 可展示已存在字段，但所有缺失字段对应的卡片隐藏。
   - 顶部提示：`证据包字段不完整，当前页面仅展示可追溯内容`。

5. **生成失败**
   - 如果证据包生成流程返回 error，三页显示错误态。
   - 主按钮：`重试生成证据包`。
   - 次按钮：`回到数据对标`。

## 8. 实施边界

本设计只重规划三个分析页面，不重做数据对标页，也不重做报告页面库。

本阶段应避免：

- 改动底层指标计算逻辑。
- 改动完整 PPT 导出流程。
- 引入新的远程模型依赖。
- 大规模重写所有旧专题模块。

可以做的最小重构：

- 新增三页 page model builder。
- 重排 `step2Content` 的页面显示职责。
- 将旧高级 mount 移入折叠区。
- 更新契约测试，确保页面只读取当前证据包。

## 9. 验收标准

### 9.1 可自动验证

1. 选择目标行和对标行后，三页均显示同一目标银行、年份和对标组。
2. 结论摘要页首屏只有总答案、三张主判断卡、核心 KPI 和下一步按钮。
3. 证据地图页首屏只有三类证据、证据强度、风险边界和跳转入口。
4. 专题归因页首屏只展示一个主专题链，其他专题和高级深钻默认折叠。
5. 证据包过期时，三页均提示重新生成，不继续使用旧内容。
6. 浏览器验证：从数据对标进入三页，内容随目标行和对标组变化。
7. 所有强判断字段必须有 `trace`；没有 trace 的判断不得以强结论样式渲染。
8. `reportCandidates` 必须包含 `id / sourceIssueId / title / chartType / evidenceSentence / recommendedSlideLayout / context / trace`。
9. 专题超过 3 个时，首屏最多显示 3 个，剩余专题进入折叠列表。

### 9.2 需人工 review

1. 三页文案是否具备咨询报告语气，而不是系统说明。
2. 禁用泛化表述是否被替换成可追溯事实表达。
3. 证据强度是否符合业务直觉。
4. 报告候选页标题是否适合进入正式汇报。

## 10. 禁用泛化表述清单

以下表述不得作为页面主判断出现：

- `需要综合分析`
- `整体表现较好/较差`
- `存在一定压力`
- `需要进一步关注`
- `建议持续优化`
- `指标有所波动`
- `需结合实际情况判断`
- `具有一定参考意义`

推荐改写规则：

- 把“存在一定压力”改为：`<指标>低于/高于对标组<差距>，并与<原因指标>方向一致，因此形成<问题链>。`
- 把“需要进一步关注”改为：`下一步应验证<具体原因指标>是否继续扩大与对标组差距。`
- 把“整体表现较好/较差”改为：`<目标银行><年份><指标>为<数值>，对标组为<数值>，差距为<差距>，证据强度为<强/中/弱>。`

## 11. 自查

- 所有章节均已给出明确要求。
- 设计聚焦三页重规划，未扩展到底层数据或完整导出。
- 页面职责没有互相重叠：结论摘要负责判断，证据地图负责证明，专题归因负责解释机制。
- 数据入口明确：默认使用已确认 evidence pack。
- 高级内容保留但默认折叠，兼顾减载和后续扩展。
