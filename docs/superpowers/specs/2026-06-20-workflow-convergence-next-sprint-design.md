# Workflow 收口与下一阶段重构设计

## 1. 背景

截至当前进度，故事线事实包链路已经完成了核心模型和下游读取：

- `js/65-storyline-fact-pack-model.js` 已提供 `storylineFactPack` 数据模型、去重、存取和运行态同步。
- `js/66-storyline-fact-pack-ui.js` 已提供右侧事实包抽屉、图表放大层和读图指南。
- `js/63-three-page-diagnosis-model.js` 与 `js/64-three-page-diagnosis-renderer.js` 已能优先读取已选故事线事实包。
- `js/61-report-page-library-model.js` 已能从 `storylineFactPack.reportCandidates` 生成报告页候选。
- 浏览器验证已能覆盖“事实包中枢 → 读图指南 → 结论摘要”的基础链路。

但最新 workflow 评估指出，运行态仍有几个关键断点：

- `js/55-benchmark-page.js` 中故事线事实包按钮接线已经在工作区实现，但混在此前未提交的大块故事线视图改动里，尚未形成干净提交。
- 数据对标页自然点击流仍不稳定：选择目标银行后不一定进入可选故事线卡片视图。
- 旧版 `bmFactPackBar` 与新版 `storylineFactPackDrawer` 并存，入口语义冲突。
- 三页诊断虽然能读事实包，但还没有完全变成固定 16:9 的“一页一个故事”播放器。
- 报告页库模型已接入事实包，但页面预览和最终 HTML 报告还没有完整按事实包图、证据句和读图指南重渲染。

本设计的目标不是重写所有功能，而是把已经完成的模型能力接到稳定用户路径上，再进入视觉和报告页升级。

## 2. 设计目标

1. **先收口，再扩展**  
   先解决 `js/55-benchmark-page.js` 混合改动、自然点击流和事实包入口冲突，再做播放器和报告页升级。

2. **保留已完成能力**  
   不重写 `storylineFactPack`、三页模型和报告页库模型；后续只补齐 UI 与真实用户路径。

3. **统一入口**  
   数据对标页的主入口统一为 `storylineFactPackDrawer`。旧 `bmFactPackBar` 降级为调试/导出入口，默认不作为主流程出现。

4. **真实路径可验证**  
   浏览器测试必须从“选择目标银行 → 看到故事线 → 加入事实包 → 打开读图指南 → 进入结论摘要”自然走通，不再依赖脚本手动 seed fact pack。

5. **一页一个故事**  
   结论摘要、证据地图、专题归因进入下一阶段时，采用固定比例故事播放器承载，每页只说一个完整故事。

## 3. 范围划分

### 3.1 本轮必须完成

- 整理并提交 `js/55-benchmark-page.js` 中事实包入口相关改动。
- 修复目标银行选择后的自然流，使用户进入数据对标后能看到故事线卡片。
- 每条故事线显示 `加入事实包 / 查看大图 / 读图指南`。
- 新版 `storylineFactPackDrawer` 成为主入口。
- 浏览器测试从真实点击流走通。

### 3.2 本轮推进但可分批完成

- 三页诊断切换为固定 16:9 故事播放器。
- 专题归因改为左侧专题列表、右侧当前专题详情。
- 报告页库 renderer 接入事实包图表、读图指南和候选页状态。

### 3.3 本轮不做

- 不重建指标库。
- 不重写完整报告导出引擎。
- 不将所有历史 `managementDiagnosisPack` 字段一次性迁移到 `storylineFactPack`。
- 不推送 GitHub，除非用户明确要求。

## 4. 关键决策

### 4.1 `js/55-benchmark-page.js` 的处理方式

采用 **小步收口**：

- 保留当前工作区中已经存在的故事线视图能力。
- 只把事实包相关入口、事件委托和测试整理成可提交状态。
- 如果无法安全拆分旧改动，则将当前 `js/55` 视为“故事线视图基线”，单独提交一条说明性 commit，后续任务在这个基线上继续。

理由：强行回退或重做会破坏用户前面已确认的故事线布局方向，也容易误删已有工作。

### 4.2 新旧事实包入口

采用 **新入口主流程、旧入口降级**：

- `storylineFactPackDrawer`：主流程入口，承担已选故事线、目标行、对标组、年份、进入诊断和报告候选。
- `bmFactPackBar`：默认隐藏或折叠到“高级导出/调试”，不再提示用户从这里进入报告分析。

### 4.3 三页诊断与播放器

采用 **轻量故事播放器**：

- 先新增一个小型 `storylinePagePlayer` renderer，不改动所有旧 section。
- 在 `answer / evidence / topics` 页面优先渲染播放器。
- 旧高级模块保留在折叠区或隐藏区，作为后续深钻能力。

### 4.4 报告页库

采用 **模型已接入、renderer 后补**：

- `js/61` 继续作为报告候选数据源。
- `js/62` 下一阶段负责把候选页中的 `sourceFactIds / chartIds / evidenceSentence / readingGuideId` 可视化。
- 缺证据候选页展示 `待补证据`，不默认进入最终报告。

## 5. 目标用户流

1. 用户进入首页，选择目标银行。
2. 系统自动设置默认对标组并进入数据对标页。
3. 数据对标页展示推荐故事线卡片。
4. 用户在故事线旁点击：
   - `加入事实包`：故事线进入右侧事实包抽屉。
   - `查看大图`：打开大图层。
   - `读图指南`：打开同一个大图层并聚焦读图指南。
5. 用户在事实包抽屉确认已选故事线，点击 `进入结论摘要`。
6. 结论摘要、证据地图、专题归因只展示事实包中的故事线。
7. 报告页库只从事实包候选页生成报告页面。

## 6. 页面与组件要求

### 6.1 数据对标页故事线卡片

每张故事线卡片必须包含：

- 故事线标题。
- 一句话结论。
- 1-3 个核心指标。
- 证据强度。
- 操作按钮：`加入事实包 / 查看大图 / 读图指南`。

按钮行为：

- `加入事实包`：调用 `ensureStorylineFactPackFromBenchmarkStory(ref)` 或等价函数。
- `查看大图`：使用当前故事线图表调用 `openStorylineChartViewer(chart)`。
- `读图指南`：同样打开图表 viewer，并显示右侧指南。

### 6.2 事实包抽屉

抽屉必须显示：

- 目标银行。
- 年份。
- 对标组数量。
- 已选故事线数量。
- 已选故事线列表。
- 进入结论摘要按钮。

下一阶段增加：

- 移除故事线。
- 生成报告候选页。
- 事实包状态：`confirmed / partial / stale / error`。

### 6.3 三页故事播放器

播放器结构：

- 固定比例画布。
- 顶部事实包上下文条。
- 中部单页故事内容。
- 底部上一页 / 下一页 / 页码。

结论摘要页只展示：

- 一句话总判断。
- 最多 3 张主判断卡。
- 最小 KPI 条。

证据地图页只展示：

- 证据强度。
- 三类证据或事实包分组。
- 证据链摘要。
- 风险边界。

专题归因页只展示：

- 专题列表。
- 当前专题四段因果链。
- 主图与读图指南。
- 1-2 个报告页候选。

### 6.4 报告页库

报告页候选必须保留：

- `storylineId`
- `sourceFactIds`
- `chartIds`
- `evidenceSentence`
- `readingGuideId`
- `recommendedSlideLayout`
- `useScenario`

未满足必填字段时：

- `status = "待补证据"`
- `selected = false`
- renderer 只显示占位说明，不生成正式报告页。

## 7. 状态与异常

- `missing-pack`：没有事实包，提示回到数据对标。
- `empty-selection`：有事实包但没有选中故事线，提示选择至少一条故事线。
- `partial-pack`：缺少图片、分类或读图指南，局部降级。
- `stale-pack`：目标行、对标组或年份变化，提示重新生成。
- `error-pack`：读取失败或生成失败，显示重试入口。
- `confirmed`：允许进入三页和报告页库。

## 8. 验收标准

### 8.1 自动验收

- 目标银行点击一次后，数据对标页能展示故事线卡片。
- 页面中存在 `加入事实包 / 查看大图 / 读图指南`。
- 点击 `加入事实包` 后，`storylineFactPack.selectedStorylineIds.length > 0`。
- 事实包抽屉显示已选故事线数量。
- 打开图表 viewer 后，能看到 `这张图看什么 / 关键差距 / 支持的判断 / 报告用途 / 数据来源`。
- 进入结论摘要后，页面内容来自 `storylineFactPack`。
- 报告页库不展示未选故事线候选页。

### 8.2 人工验收

- 数据对标页的故事线选择入口是否足够明显。
- 旧事实清单入口是否不再干扰主流程。
- 结论摘要是否能在 30 秒内读完。
- 专题归因是否一次只聚焦一个问题链。
- 报告页预览是否像一页完整 PPT，而不是数据块堆叠。
